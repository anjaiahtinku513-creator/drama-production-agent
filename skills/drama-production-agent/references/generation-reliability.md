# 生成可靠性与通道适配

用于实际制作前、异步查询、结果未知恢复和产物取回。提取 miora-video-studio 的通用方法，与 [生产状态](production.md) 合用；没有 Miora/WorkBuddy 依赖，不包含其连接器或计费能力。

## 提交前

只发现当前阶段需要且项目已经允许的工具。视频仍遵守 [待接入约定](video-integration.md)，工具列表出现视频服务不能自动改变项目供应商。

核实实际模式、模型、画幅、分辨率、时长、参考接收方式/上限、声音能力、提示词长度以及任务查询/取消能力。参数可来自已有项目或真实工具默认值，不能因为上游某通道要求用户声明四项，就反复索取已知值。无法确定影响交付的参数时汇总缺项；准备文字稿时可以明确待绑定项。

超过能力时给出拆镜、拆组或更换受限方案；不要静默裁掉关键参考、改分辨率或压缩对白。完整审核稿与实际请求保留对应关系。

提交前保存 action、镜头/组 ID、输入版本与摘要、请求参数、参考绑定。只保存必要非敏感信息；密钥与临时令牌留在安全配置。

## 查询与恢复

收到真实 task ID 后绑定到该 action，查询同一任务。长任务按工具支持的间隔等待，并向用户同步实质进度；不把某历史生成分钟数当成保证。不为常规等待自动创建定时任务。

超时、进程中断、返回丢失与查询暂时失败都不能证明生成失败。先只读查询平台状态及明确属于本 action 的产物，恢复同一作业。没有查单能力时记录限制，保持 submission_unknown，不按普通失败重交。

有明确“未接收”或可重试失败证据，且原授权覆盖费用/次数时再重试。新的生成是新的 action 版本。取消只有平台支持并确认后才记成功。

## 文件归属与核验

task ID 对应的官方结果与返回路径优先。共享目录中的“最新/最早文件”、相似时长、文件名或修改时间均不足以独立证明并发作业归属。缺绑定时保留候选并标 needs_review，不认领其他作业文件。内置 image_gen 无 task ID 时使用该次调用实际返回的图片与文件证据。

取回项目内的版本化路径，核对文件已写完、可解码，读取实际时长、尺寸、画幅、帧率与音轨，保存 SHA-256。同一摘要用于后续验收。文件头证明规格，不能证明表演、动作、对白或口型；视觉与听检按 [质检](quality.md) 执行。

## 可选供应商适配

用户将来指定 Miora 或其他供应商时，读取当次真实 schema 和服务说明，再填写能力来源、认证方式、请求/查询/结果映射和测试状态。上游的 WorkBuddy 路径、临时凭据方式、历史分辨率/参考上限不作为星幕事实；本插件不修改外部信任记录，不扫描用户无关媒体目录。

接入前可以准备模板，只有授权的实际最小镜头验证成功后才标 verified。接口声明与本机实测差异记录在供应商适配中，不扩散成所有项目的默认规则。
