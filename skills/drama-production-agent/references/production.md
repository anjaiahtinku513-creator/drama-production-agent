# 生产、依赖与恢复

实际提交、恢复与取回同时读 [生成可靠性](generation-reliability.md)，参数闸门和文件归属按该方法执行。现有状态和 project.json 结构保持兼容。

## 能力发现

只检查当前阶段实际需要的能力，可从文本、图像、视频、语音、口型、音乐/音效、剪辑、媒体检查中选择；必要时列简短表，每项写工具及 `available / unverified / unavailable`。只有实时可调用且满足需求才标 available；局部文字返修不必发现全部媒体服务。缺少某项时完成独立的创作工作，并说明缺口。不要自行安装软件、登录、上传或调用付费服务来伪造“全自动已接通”。

图像固定读取 [内置图像生成](builtin-image.md) 并使用 Codex image_gen；视频保持待接入，不主动选择现成视频服务。未来接入按 [视频接入约定](video-integration.md) 执行。语音和剪辑只读取当次实际使用工具的技能。具体参数与限制由实时接口确认。

## 生成前的可审核批次

内置 image_gen：用户请求生成相应图片即覆盖该范围内的内置图像调用，先准备提示词和引用，再执行；不要求额外 API Key、虚构价格或逐图重复确认。若出现真实额度/计费限制则如实说明，不能擅自换服务。本次仅配置工作流并不意味着应生成测试图片。

额外付费外部服务：完成提示词和引用素材以后，给出项目/集/镜头范围、供应商与模型、数量、时长/分辨率、传输素材、可核实费用或未知费用、预算上限、返修次数和交付目标。查阅已有授权；完全覆盖时执行，无需重复问。未知费用不声称零成本。

生产计划中的每个 action 对应一次媒体制作操作。提交前保存动作身份、输入版本与摘要；异步外部服务返回后记录 provider task ID。内置 image_gen 直接返回图片时可从 submitting 进入 retrieved，以实际返回文件和摘要作为证据；没有 task ID 就保持 null，不伪造平台查单能力。台账不保存密钥、Cookie、完整签名 URL。

## 状态含义

`planned → submitting → submitted → retrieved → accepted`

其他状态：`submission_unknown`、`failed`、`needs_review`、`stale`。它们不是成功。

- `planned`：完整参数已准备，但尚未提交。
- `submitting`：发出调用前持久化；进程重启后若缺 task ID，先按结果未知处理。
- `submitted`：收到可核对的任务 ID；尚不表示生成完毕。
- `submission_unknown`：超时/断线，无法判断平台是否接收。查平台或等待核对；禁止按普通失败直接重交。
- `retrieved`：实际文件落地并计算 SHA-256。
- `accepted`：适用技术、视觉、听检均完成，有观察证据且绑定同一文件摘要。
- `stale`：上游改变使该产物不再适用；文件保留但不能直接交付。

只对已知可重试的失败作有界重试。付费重生必须落在授权预算和次数中；普通状态查询不应产生新生成任务。预算没有余量即停在可恢复状态。客户端动作 ID 不代表供应商支持幂等请求。

## 项目状态记录

初始化器的 `project.json` 中 `actions`、`deliverables` 默认空。只有生产发生时才写条目；创意阶段无需为每句话建账。可用下列条目结构，不复制示例值冒充真实证据：

```json
{
  "id": "EP001-S010-video-v1",
  "kind": "video",
  "state": "planned",
  "provider": "实际供应商",
  "model": "实际模型",
  "input_revision": "分镜版本",
  "input_digest": "提交输入的SHA256",
  "depends_on": [],
  "task_id": null,
  "path": null,
  "sha256": null,
  "qa": []
}
```

验收记录 `qa` 的每项包含 `check`（technical/visual/audio）、`result`（pass/fail/not_applicable）、`evidence`（实际观察、工具结果或报告路径）、`sha256`（被检查素材摘要）。not_applicable 必须解释理由。图片需要 technical/visual；音频需要 technical/audio；视频需要三项。听检工具不可用时标未完成，不以存在音轨代替。

最终成片也记为 `kind: video` 的 action，依赖实际参与剪辑的素材 action；其 ID 进入 `deliverables`。仅所选成片及其依赖决定交付就绪；废弃候选单独保留不阻塞替代版本。

`project.py status` 检查字段、依赖、实际文件摘要及验收记录完整性，但它不能鉴别审片文字是否真实，更不能代替视觉/音频检查。不要让脚本的通过结果充当独立艺术质量证明。

## 最小返修

区分问题源：剧本因果、资产身份、关键帧构图、视频运动、声音、剪辑。优先修最早出错层，再重新生成受影响的下游。例：第4镜道具换手，先核对前后镜持物；若前后都正确，仅修第4镜；若第5镜承接错手，则同时使第5镜失效。换一张角色基准图会影响所有绑定它的镜头，不能只改文件名。

保留旧文件与判断；建立新版本 action，不在旧版本下覆盖已验收素材。选用新版本后更新成片依赖，重新做最终连续播放检查。

## 提示词版本与出站编译

作业归属优先用该 task 的官方结果或调用返回路径。共享目录的最新文件或相似规格不能独立证明归属；缺乏绑定时保留 needs_review，不按 retrieved/accepted 放行。接口 completed 之后仍检查真实文件可解码、实际规格及适用验收。

生成前按 [导演提示词标准](director-prompt-standard.md) 完成全文与逐段请求。保存本轮提示词版本和参考绑定；后段依赖前段实际尾帧时，前段重生使旧绑定失效。未获取尾帧时保留待绑定，不提交旧帧冒充新版。用户只审核/优化文字时，不因此重生媒体或改写已完成任务的输入记录。
